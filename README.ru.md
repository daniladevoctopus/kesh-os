## 🎯 Целевое железо и философия

Современные десктопные операционные системы оставили за бортом ПК 2011–2016 годов:

* **Windows 10** официально завершила жизненный цикл в октябре 2025 года.
* **Windows 11** требует жёстких аппаратных ограничений (Intel 8-го поколения / AMD Zen+, TPM 2.0, от 4 ГБ ОЗУ).
* Современные дистрибутивы Linux (GNOME/KDE) с фоновыми демонами и systemd зачастую потребляют слишком много ресурсов на системах с 2–4 ГБ памяти.

**KeshOS** создана, чтобы дать быструю, визуально отзывчивую систему для этих 64-битных машин, потребляя **~150 МБ ОЗУ в простое** без фоновой телеметрии и избыточных служб.

## 🛠 Архитектура и стек технологий

```text
+-------------------------------------------------------+
|  Ring 3 (Пространство пользователя)                   |
|   - KeshShell (C++ оконный композитор)                |
|   - Нативные приложения: Dolphin, Notepad, TaskMgr    |
|   - Нативные пакеты .kea со связью через syscall      |
+-------------------------------------------------------+
|  (Системные вызовы: быстрый SYSCALL/SYSRETQ и IPC)    |
+-------------------------------------------------------+
|  Ring 0 (Монолитное ядро)                             |
|   - 4-уровневая страничная адресация (PML4)           |
|   - Сетевой стек ядра (ARP, ICMP, DNS-резолвер)       |
|   - Unix-подобная VFS (/, /apps, /system, /hdd)       |
|   - Драйверы хранения: IDE ATA, ATAPI CD-ROM, FAT32   |
+-------------------------------------------------------+
|  (Протокол загрузки Limine)                           |
+-------------------------------------------------------+
|  Железо и прошивка: x86_64 UEFI (GOP) и Legacy BIOS   |
+-------------------------------------------------------+
```

### 1. Подсистема загрузки
* Загрузка через **Limine Bootloader**, поддерживающий как современные конфигурации UEFI/GPT, так и классический BIOS.
* Инициализация линейного кадрового буфера высокого разрешения через UEFI GOP.

### 2. Ядро и управление памятью
* **Монолитная архитектура** на C и x86_64 Assembly.
* Управление памятью через **4-уровневую страничную адресацию (PML4)** с разделением виртуальных адресных пространств ядра и процессов.
* **Аппаратная изоляция Ring 3:** ошибки и сбои в юзерспейс-приложениях перехватываются прерываниями ядра (`#GP`, `#PF`, `#UD`) без падения сессии ОС и композитора.

### 3. Графическая подсистема и композитор (KeshShell)
* Собственный оконный композитор на C++.
* Приложения рендерят в изолированные разделяемые внеэкранные буферы поверхностей (`0x50000000`).
* Композитор выполняет z-сортировку, оформление окон ("светофорное" управление, адаптивный стиль) и блиттинг изменённых областей в двойной буфер.
* Асинхронная маршрутизация мыши и клавиатуры через очередь событий системных вызовов (`SYS_POLL_EVENT`).

### 4. Сетевой стек
* Встроенный сетевой стек ядра с поддержкой Intel **e1000** Gigabit Ethernet:
  * Обработка Ethernet-кадров и динамический кэш ARP.
  * Модуль ICMP для сетевой диагностики (`ping`).
  * Прямой DNS-резолвер для разрешения доменных имён по UDP.
  * Базовый модуль TLS на основе BearSSL.

### 5. Пакеты приложений и файловая система
* **Пакеты `.kea`:** собственный формат исполняемых файлов на базе ELF64 со структурированными заголовками метаданных и иконками.
* **Unix-подобная VFS:** древовидная структура (`/`, `/apps`, `/system`, `/hdd`, `/cdrom`) с поддержкой оперативной памяти (RAMFS), FAT32 и ISO 9660.
* **Файловый менеджер Dolphin:** современный файловый менеджер на C++ с навигацией по путям, режимами сетки и списка, а также мониторингом накопителей.

* **Ядро:** PMM/VMM, таблицы PML4, контекстное переключение Ring 3, IPC, C++ композитор, драйверы устройств и сетевые протоколы написаны вручную.

## 🚀 Сборка и запуск из исходников

### Требования

Для сборки необходимы установленные инструменты:

* **LLVM / Clang** (`clang`, `clang++`, `ld.lld`) или `x86_64-elf-gcc`
* **NASM** (ассемблер x86_64)
* Система сборки **Ninja** и **Python 3**
* **xorriso** (для создания загрузочного ISO-образа)
* **QEMU** или **VirtualBox** (для тестирования)

### 1. Генерация графа сборки и компиляция ядра

Сборка KeshOS автоматизирована через связку Python и Ninja:

```bash
# Генерация файла build.ninja
python generate_ninja.py

# Компиляция ядра, драйверов, композитора и юзерспейс-приложений
ninja
```

*(Также можно использовать команду `make` или `make all`).*

### 2. Сборка загрузочного ISO-образа

Упаковка бинарников Limine, ядра и пакетов `.kea` в ISO:

```powershell
# В Windows (PowerShell):
powershell -ExecutionPolicy Bypass -File .\build-iso.ps1

# Либо через Makefile:
make iso
```

Результат: `build/keshos.iso`.

### 3. Запуск в виртуальной машине

#### Запуск через QEMU:
```powershell
powershell -ExecutionPolicy Bypass -File .\run-qemu.ps1
# или
make qemu
```

#### Запуск в VirtualBox:
1. Создайте виртуальную машину с типом **Other / Unknown (64-bit)**.
2. Выделите **1024 МБ – 2048 МБ** ОЗУ и **32 МБ – 64 МБ** видеопамяти.
3. В меню **Система -> Материнская плата -> Порядок загрузки** поставьте **Оптический диск** первым.
4. Подключите `build/keshos.iso` в оптический привод.
5. Для работы сети выберите сетевой адаптер **Intel PRO/1000 MT Desktop (82540EM)**.
6. Запустите виртуальную машину!
