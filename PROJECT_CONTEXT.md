# KeshOS — Project Context & Developer Handover Guide

> **Назначение файла:** Полная компактация контекста проекта, архитектуры, установленных правил кодинга, стиля и текущего состояния для плавной передачи контекста любой новой модели / ассистенту.

---

## 1. Основные Правила и Конвенции (КРИТИЧНО)

### 💬 Правило комментариев в коде
- **В коде (.c, .cpp, .h, .asm):** Максимум **1–2 комментария на весь файл** (только если действительно нужно пояснить нетривиальный момент). Никаких комментариев к каждой строке или очевидным функциям.
- **В Makefile / build.ninja / PowerShell / скриптах сборки:** **КОММЕНТАРИИ СТРОГО ЗАПРЕЩЕНЫ (0 комментариев)**. Писать чистый лаконичный конфиг/скрипт без `#` или `//`.

### 🚫 Запрет на маркетинговый / "вайбкод" мусор (Buzzwords)
- **Строго запрещены** фразы вроде: `"Liquid Glass Engine"`, `"Optical Phase"`, `"Neural Hyper-Compositor"` и прочие выдуманные "технологии".
- Нужна **строгость, техническая точность и аккуратный минимализм**. В About и интерфейсе пишем реальные технические обозначения (например: `Render: Composited Desktop`, `Kernel: KeshOS x86_64`).

### 🏷️ Брендинг и Стиль
- **Название ОС:** `KeshOS`
- **Разработчик / Компания:** `SneakDeak Tech`
- **Визуальный стиль:** Элементы macOS-стиля (аккуратный док, гладкие скругления, акцентные цвета, читабельная типографика, плавные анимации), но ОС самобытная, строгая.
- **Экран Kernel Panic:** Выполнен в фирменном стиле (смесь лаконичности macOS и информативности BSOD, брендинг KeshOS, без следов чужих ОС вроде IgorOS).
- **Никаких плейсхолдеров:** Все графические ассеты и иконки должны быть реальными и качественными (без серых квадратов и "TODO").

### 🤝 Взаимодействие с пользователем
- **Общение:** На русском языке, неформально ("на ты"), лаконично и по делу.
- **Тестирование:** Пользователь **всегда тестирует ОС сам в QEMU**. Ассистенту не нужно самостоятельно запускать QEMU через фоновые процессы.

## 2. Архитектура Проекта

KeshOS — 64-битная модульная операционная система (x86_64) с гибридной архитектурой оконных приложений.

```
keshoos/
├── boot/                   # Загрузчик (Limine) и конфиги загрузки
├── include/                # Ядерные заголовочные файлы (kesh/*)
├── kernel/                 # Ядро, менеджер окон (uwindow.c/h), системные вызовы
├── src/                    # Драйверы, GUI-подсистема, десктоп
│   ├── desktop.c           # Композитор рабочего стола, панель задач, Пуск, Док
│   ├── gui/
│   │   ├── anim/           # Системы анимаций (genie_anim и др.)
│   │   └── apps/           # Встроенные Ring 0 приложения (C)
│   │       ├── about/      # О системе (About)
│   │       ├── doom/       # Порт DOOM
│   │       ├── terminal/   # Терминал
│   │       ├── files/      # Файловый менеджер
│   │       ├── calc/       # Калькулятор
│   │       ├── music/      # Музыкальный плеер
│   │       └── settings/   # Настройки (Ring 0)
│   └── drivers/            # Сеть, графика, диск, устройства ввода
├── userspace/              # Пространство пользователя (Ring 3)
│   ├── include/            # Библиотеки юзерспейса (kea.h, libc)
│   └── apps/               # Юзерспейс-приложения (.kea)
│       ├── notepad/        # Текстовый редактор
│       ├── explorer/       # Проводник Dolphin
│       ├── taskmgr/        # Диспетчер задач
│       ├── paint/          # Графический редактор
│       └── settings/       # Настройки (C++ версия)
├── ready/                  # Корневая файловая система для ISO (содержит wm.conf, обои, .kea)
├── build/                  # Скомпилированные бинарники и keshos.iso
└── kpm/                    # Пакетный менеджер / утилиты KeshOS
```

### Ring 0 vs Ring 3 Приложения
1. **Ring 0 Apps (вкомпилированы в ядро):**
   - Находятся в `src/gui/apps/`
   - Написаны на чистом C
   - Прямой доступ к оконной системе и буферу кадра
   - Список: Terminal, Files, DOOM, Calculator, Settings (Ring0), Music, About
2. **Ring 3 Apps (User Space .kea executables):**
   - Находятся в `userspace/apps/`
   - Формат исполняемых файлов: **KEA** (упаковываются утилитой KEA-PACK)
   - Общаются с ядром через системные вызовы (`userspace/include/kea.h`)
   - Список: Notepad, Explorer ("Dolphin"), TaskMgr, Paint, Settings (C++)

## 3. Оконная система и GUI

- **Менеджер окон:** `kernel/uwindow.c` и `kernel/uwindow.h`. Поддерживает до 8 активных окон юзерспейса (`user_window_t`), заголовок 30px, кнопки управления с поддержкой выравнивания слева/справа (`g_window_controls_align`).
- **Композитор:** `src/desktop.c`. Рендерит обои, док, панель задач, меню Пуск и композитит окна.
- **Система анимаций:**
  - **Открытие окон (Ring 3):** `anim_state = 1` в `uwindow.c` — scale 85% → 100% с функцией ease-out (~10 кадров).
  - **Закрытие окон (Ring 3):** `anim_state = 2` в `uwindow.c` — scale 100% → 78% с ease-in + fade, после завершения посылается `EVENT_CLOSE`.
  - **Меню Пуск:** Slide-up/fade-in при открытии, slide-down/fade-out при закрытии (`s_menu_anim_t` в `desktop.c`).
  - **Вкладки настроек:** Скользящая плашка-индикатор и плавное появление контента.
  - **Genie Animation:** Для окон About и Music через `src/gui/anim/genie_anim.h/c`.

## 4. Сборка Проекта

- **Инструменты:** Clang (x86_64 cross-target), NASM, Python (генератор `generate_ninja.py`), Ninja, PowerShell (`build-iso.ps1`).
- **Загрузчик:** Limine (`boot/limine/limine.conf`).
- **Команды сборки:**
  ```powershell
  ninja
  ./build-iso.ps1
  ```
- Результат сборки: `build/keshos.iso`.

## 5. Важные нюансы и решенные баги

1. **Заголовок Проводника:** Окно юзерспейс-проводника имеет заголовок `"Dolphin"` (НЕ `"Explorer"`). Поиск окна должен производиться по подстроке `"Dolphin"`.
2. **Индикаторы в панели задач:** Ранее все Ring3 приложения имели одинаковый ID `WIN_ID_USER_APP`. Исправлено: статус активности на панели задач проверяется по уникальным заголовкам окон (`Notepad`, `TaskMgr`, `Paint`, `Dolphin`).
3. **Фокус окон:** `g_focused_win_id` является `static` внутри `kernel/uwindow.c`. Для внешнего доступа используется функция `uwindow_is_focused_idx(int idx)`.
4. **Перетаскивание окон (Drag):** В `kernel/uwindow.c` координаты окна обновляются до вычисления координат отрисовки `draw_x`/`draw_y`, чтобы избежать задержки и артефактов при драге.
5. **Предупреждение о NULL:** Предупреждение о переопределении макроса `NULL` между флагами сборки и `doom/fs_include/stddef.h` безвредно.
6. **Сборка ISO образа:** Для создания ISO используется `xorriso` (из тулчейна KeshBE), формирующий стандартный El Torito образ как для BIOS (`limine-bios-cd.bin`), так и для UEFI (`limine-uefi-cd.bin`). Попытки ручной байтовой генерации ISO приводили к отсутствию дескрипторов и падению VirtualBox в сетевую загрузку iPXE.
