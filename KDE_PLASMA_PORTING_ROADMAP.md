# 🚀 Дорожная карта портирования KDE Plasma и Wayland на KeshOS

Данный документ описывает полный технический план перехода KeshOS на современную графическую архитектуру: запуск официального стека **Wayland** и полноценного окружения рабочего стола **KDE Plasma (Ring 3)**.

---

## 🏛️ Архитектурный стек: как Plasma работает поверх ядра

```
+------------------------------------------------------------------+
|                      KDE Plasma (plasmashell)                    |
|   (Нижняя панель, меню Kickoff, системный трей, обои, плазмоиды)   |
+------------------------------------------------------------------+
|                   Qt 6 & KDE Frameworks (KF6)                    |
|     (QtQuick, QML Engine, QtCore, QtGui, libKF6Plasma, QWayland)  |
+------------------------------------------------------------------+
|                 Библиотеки интерфейса и шрифтов                  |
|          (libwayland-client, FreeType, Fontconfig, Pixman)       |
+------------------------------------------------------------------+
|               Wayland-композитор (Дисплейный сервер)             |
|   (Принимает буферы от Plasma/окон, композитит сцену, шлёт ввод) |
+------------------------------------------------------------------+
|                   Стандартная библиотека C (Libc)                |
|           (musl libc + динамический линковщик ld-musl.so)        |
+------------------------------------------------------------------+
|========================= Системные вызовы =======================|
|                      Ядро KeshOS (Ring 0)                        |
|  - Framebuffer VRAM (вывод пикселей на дисплей)                  |
|  - UNIX Domain Sockets (`AF_UNIX` + `SCM_RIGHTS`)                |
|  - Разделяемая память (`mmap`, `memfd_create`)                   |
|  - Драйверы ввода (PS/2 / USB мышь и клавиатура)                 |
|  - Планировщик потоков, VFS, epoll/poll                          |
+------------------------------------------------------------------+
```

---

## 📋 Поэтапный план реализации (Roadmap)

### Фаза 0: POSIX-совместимость и стандартная библиотека (`musl libc`) [ВЫПОЛНЕНО]
> **Цель:** Перестать писать кастомный рантайм для каждой программы и запустить официальный компилятор под KeshOS.

- [x] **0.1. Расширение набора системных вызовов Linux/POSIX в `kernel/linux_syscall.c`:**
  - [x] Управление памятью: `SYS_mmap`, `SYS_munmap`, `SYS_mprotect`, `SYS_brk`.
  - [x] Файлы и VFS: `SYS_open`, `SYS_openat`, `SYS_close`, `SYS_read`, `SYS_write`, `SYS_lseek`, `SYS_stat`, `SYS_fstat`, `SYS_fcntl`, `SYS_poll`.
  - [x] Потоки и окружение: `SYS_arch_prctl` (MSR 0xC0000100 FS_BASE), `SYS_set_tid_address`, `SYS_exit`, `SYS_exit_group`.
  - [x] Идентификаторы и сигналы: `SYS_getpid`, `SYS_rt_sigaction`, `SYS_rt_sigprocmask`, `SYS_uname`.
  - [x] Таймеры: `SYS_clock_gettime` (`CLOCK_MONOTONIC`, `CLOCK_REALTIME`).
- [x] **0.2. Портирование `musl libc`:**
  - [x] Настроена кросс-компиляция `musl 1.2.5` под таргет `x86_64-unknown-linux-musl`.
  - [x] Собрана постоянная статическая `libc.a`, `crt1.o`, `crti.o`, `crtn.o` в `toolchain/musl/lib/`.
  - [x] Проверена сборка стандартного "Hello World" на Си через `clang -target x86_64-unknown-linux-musl` (`ready/boot/apps/hello.elf`).
- [x] **0.3. ELF-стек Linux и TLS:**
  - [x] Обновлен стек при загрузке ELF (`argc=1, argv[0], envp=NULL, auxv: AT_PAGESZ, AT_PHDR, AT_PHENT, AT_PHNUM, AT_ENTRY, AT_RANDOM, AT_EXECFN`).
  - [x] Поддержка переключения `MSR_FS_BASE` при контекстном переключении процессов (`process_switch`).

### Фаза 1: Межпроцессное взаимодействие (IPC) для Wayland [ВЫПОЛНЕНО]
> **Цель:** Предоставить юзерспейсу низкоуровневые механизмы, без которых Wayland в принципе не может передавать кадры.

- [x] **1.1. UNIX Domain Sockets (`AF_UNIX`):**
  - [x] Реализация двусторонних потоковых сокетов в пространстве ядра (`socket(AF_UNIX, SOCK_STREAM, 0)`, `bind`, `listen`, `connect`, `accept`, `socketpair`).
  - [x] Поддержка адресации через пути в файловой системе (например, `/tmp/wayland-0`).
- [x] **1.2. Передача файловых дескрипторов (`SCM_RIGHTS`):**
  - [x] Реализация передачи вспомогательных данных в `SYS_sendmsg` / `SYS_recvmsg`.
  - [x] Передача файлового дескриптора буфера памяти от клиента (Plasma) к серверу (композитор) без копирования данных.
- [x] **1.3. Разделяемая память (`Shared Memory`):**
  - [x] Системный вызов `SYS_memfd_create` (создание анонимного файлового дескриптора в ОЗУ с `ftruncate`).
  - [x] Возможность отобразить один и тот же физический фреймбуфер окна в адресное пространство двух разных процессов через `mmap` (`unix_memfd_mmap` / `process_vm_map_phys`).
- [x] **1.4. Мультиплексирование ввода-вывода (`epoll`):**
  - [x] Системные вызовы `SYS_epoll_create1`, `SYS_epoll_ctl`, `SYS_epoll_wait` для организации эффективного событийного цикла (Event Loop) в композиторе.

### Фаза 2: Сборка Wayland и дисплейного сервера (Композитора) [ВЫПОЛНЕНО]
> **Цель:** Запустить в юзерспейсе KeshOS дисплейный сервер, слушающий сокет `/tmp/wayland-0`, и вывести через него первое Wayland-окно.

- [x] **2.1. Сборка ядра библиотеки Wayland:**
  - [x] Собрать и верифицировать утилиту генерации кода `wayland-scanner` (1.26.0).
  - [x] Собрать библиотеку сервера `libwayland-server.a` (1.26.90).
  - [x] Собрать библиотеку клиента `libwayland-client.a` (1.26.90).
  - [x] Собрать и интегрировать `libffi.a` (3.8.0) для динамической диспетчеризации замыканий x86_64.
  - [x] Установить заголовочные файлы в `toolchain/musl/include/wayland/`.
- [x] **2.2. Серверный композитор KeshOS и поддержка протоколов:**
  - [x] Поддержка Linux POSIX вызовов: `open`, `openat`, `fstat`, `stat`, `fcntl`, `poll`.
  - [x] Расширение системных вызовов KeshOS GUI для Ring 3 Linux-приложений (создание изолированного окна, обновление, поллинг событий).
  - [x] Реализация протоколов Wayland Core:
    - `wl_display` (управление дисплеем, event loop).
    - `wl_shm` (пулы разделяемой памяти и форматы пикселей XRGB8888 / ARGB8888).
    - `wl_client` (управление клиентскими подключениями через AF_UNIX сокеты).
- [x] **2.3. Проверка:**
  - [x] Собрать и слинковать демонстрационный юзерспейс-бинарник `ready/boot/apps/wayland_demo.elf` (209 КБ).
  - [x] Подключение клиента к дисплейному серверу, выделение shared-memory буфера 800x600 (1.92 МБ), градиентная отрисовка и цикл событий.
  - [x] Интеграция команды `wayland` / `wl` в консоль KeshOS Recovery Mode.

### Фаза 3: Базовый стек рендеринга, ввода и шрифтов [ВЫПОЛНЕНО]
> **Цель:** Подготовить графические библиотеки, стек ввода и векторных шрифтов, от которых зависит GUI и Qt.

- [x] **3.1. Библиотеки форматов и 2D-растеризации:**
  - [x] `zlib` (138 КБ статическая библиотека `libz.a`).
  - [x] `pixman` (0.46.5, 1.2 МБ `libpixman-1.a` с SSE2/SSSE3/MMX).
  - [x] `libxkbcommon` (1.14.0, 651 КБ `libxkbcommon.a` для парсинга и трансляции раскладок клавиатуры XKB).
- [x] **3.2. Шрифтовой векторный движок FreeType 2:**
  - [x] Собрана статическая библиотека `libfreetype.a` (1.15 МБ) с поддержкой TTF/OTF, хинтинга, CFF, SDF и TrueType.
  - [x] Установлены заголовки в `toolchain/musl/include/freetype2/`.
  - [x] Интегрированы векторные шрифты `OpenSans.ttf` и `Hack.ttf` в `/boot/fonts/`.
- [x] **3.3. Подсистема ввода (evdev) и дисплея (fbdev/DRM) в ядре KeshOS:**

## ⏱️ Оценка трудоемкости и ключевые сложности

| Этап | Сложность | Главный вызов |
| :--- | :--- | :--- |
| **Фаза 0: Musl Libc** | Средняя | Дописать ~50 недостающих сисколлов в ядре (futex, clone, mmap). |
| **Фаза 1: IPC / Wayland shm** | Средняя | Реализовать передачу FD через сокеты (`SCM_RIGHTS`) и `memfd`. |
| **Фаза 2: Wayland композитор** | Средняя | Разобраться в стейт-машине протокола Wayland и буферах shm. |
| **Фаза 3: Библиотеки (PNG, Freetype)** | Низкая | Обычная пересборка стандартных Си-библиотек поверх `musl`. |
| **Фаза 4: Qt 6 & QML** | Высокая | Долгая сборка Qt, настройка программного рендеринга (no-OpenGL). |
| **Фаза 5-6: KDE Plasma** | Высокая | Большое дерево зависимостей C++/QML, конфигурация путей в VFS. |

## 📌 Что даёт этот шаг KeshOS?
1. **Настоящая модульность:** Графика полностью выносится из ядра. Если упадёт интерфейс или виджет, ядро ОС продолжит работать без паники.
2. **Любые оболочки на выбор:** Можно запускать не только KDE Plasma, но и Sway, Hyprland, XFCE или легковесные лаунчеры.
3. **Запуск софта Linux:** Полноценный `musl libc` позволит запускать компиляторы, утилиты, эмуляторы и игры без переписывания исходного кода.
